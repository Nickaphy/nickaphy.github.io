# AGENTS.md

## Project

Nicklas's personal website — a portfolio + security writeups site, meant to replace bare GitHub repo links as his career-facing portfolio. Terminal/hacker-minimal aesthetic: dark background, monospace font, single accent color. Fully static site, no JS framework.

## Important: this is a learning project

Nicklas is writing the HTML/CSS/JS himself to actually learn front-end fundamentals (his first real JavaScript). That's intentional, not a gap for an agent to fill. If you are an AI coding agent working in this repo:

- Do not write full files or large code blocks unprompted.
- Prefer explaining the approach and showing a short example; let Nicklas write the implementation.
- Point out bugs or issues rather than silently fixing them, unless explicitly asked to just fix it.
- Small, explained diffs beat large autogenerated ones.
- The Python build script (`build.py`) is tooling, not the learning focus — more license to write or fix that directly if asked.

## Tech stack

- **Frontend**: plain HTML, CSS, JavaScript. No frameworks (React/Vue/Blazor/etc.), no CSS utility frameworks. Vanilla only — that's a deliberate choice, not a placeholder for "add a framework later."
- **Build tooling**: a Python script (`build.py`) converts Markdown posts into static HTML via shared templates. Uses the `markdown` package (with `fenced_code`/`codehilite` extensions) plus `pygments` for code syntax highlighting.
- **Hosting**: GitHub Pages, deployed by pushing to `main`. No server, no build service.

## Folder structure

- `content/posts/*.md` — writeup source files. Each starts with simple frontmatter (`title`, `date`, `tags`) followed by the markdown body.
- `templates/` — shared HTML fragments (header, nav, footer) every page gets wrapped in.
- `assets/css/`, `assets/js/`, `assets/img/` — static assets.
- `build.py` — reads `content/posts/`, renders each post through the templates, and regenerates the writeups index page.
- `docs/` — build output. This is what GitHub Pages actually serves. **Never hand-edit anything in here** — it's regenerated by `build.py` and manual edits get silently overwritten on the next build.
- `requirements.txt` — Python deps for the build (`markdown`, `Pygments`).

## Commands

- Build: `python build.py`
- Preview locally: `python -m http.server --directory docs 8000`, then open `localhost:8000`
- Deploy: commit, then `git push` (GitHub Pages serves `docs/` on push to `main`)

## Conventions

- Theme colors live as CSS custom properties in `assets/css/theme.css` (background, text, accent) — don't hardcode colors elsewhere.
- Keep JS small and commented — favor readability over cleverness.
- Writeup body copy renders inside a max-width column (~700px) with line-height ≥ 1.6 — this is long-form reading, not a full-bleed layout.
- Don't introduce a JS or CSS library/framework without asking first.
